Where the model runs

1. Local AI overview

Local AI means the model performs inference on a computer you control instead of sending every prompt to a hosted model provider.

Ollama

A straightforward local model runner with a command-line interface and local API. It is especially useful for scripts, servers, Raspberry Pis, and developers who want a small set of commands.

ollama list
ollama run gemma3:1b
ollama ps

Ollama documentation ↗

LM Studio

A desktop application for discovering, downloading, chatting with, and serving local models through a visual interface. It is often friendlier for someone who prefers menus over terminal commands.

Current support includes Apple silicon Macs and supported Windows and Linux systems; check its requirements before installing.

Local does not automatically mean private or safe

A local app can still save chat history, call online tools, expose a network port, or read files you give it. Check the whole workflow—not only the location of the model.

Fit the model to the machine

2. Model size constraints

A model must fit alongside the operating system, the model runner, its working memory, and everything else using the computer.

Four numbers to notice

  • Parameters: a rough signal of model capacity—not a quality guarantee.
  • Download size: storage used by the model file.
  • Runtime memory: RAM or VRAM needed while the model is loaded.
  • Context length: how much text the model can consider; more context uses more memory.

Quantization

Quantization stores model numbers with less precision. That usually makes a model smaller and easier to run, with some possible quality tradeoff.

Important: a model’s parameter count is not the same as its file size or exact memory requirement. Check the specific model tag.

Practical starting point for a 16 GB Raspberry Pi 5

Model rangeClassroom expectationGood decision
About 1–3B parameters, quantizedBest starting range; modest download and more memory headroomBegin here
About 4–8B, quantizedMay run, but responses can be noticeably slower and context needs headroomTest before relying on it
Around 12B and aboveIncreasingly awkward for a 16 GB Pi; fitting is not the same as being pleasant to usePrefer stronger hardware or a cloud model

These are teaching guidelines, not guarantees. Architecture, quantization, context, other processes, cooling, and task all affect the result. For a quick Pi demonstration, gemma3:1b is a sensible small starting point.

The suitcase test

A model may technically fit in memory the way an overstuffed suitcase technically closes. Leave working room for context, the operating system, and the rest of the application.

Help contain agent actions

3. Docker Sandboxes security overview

A coding agent may run commands, install packages, edit files, and use network services. Docker Sandboxes place that work inside a lightweight microVM with its own kernel, filesystem, network, and Docker daemon.

What the boundary helps with

  • Separates sandbox processes from host processes.
  • Limits host file access to deliberately shared workspaces.
  • Adds network and credential controls.
  • Lets experiments make a mess inside a disposable environment.

What people still decide

  • Which project files enter the sandbox.
  • Which websites and services it may reach.
  • Which credentials or permissions are available.
  • Whether the proposed code is safe and correct.

A sandbox helps; it does not fix security

The agent controls what happens inside its environment. Shared files, permitted network destinations, credentials, generated code, and anything you later publish still require human review. Clone mode adds another useful review point by keeping the agent’s changes in a private Git clone.

From files to a public address

4. Git, GitHub, Vercel, and domains

These tools do different jobs. You do not need to memorize commands to understand the path.

Tool or ideaIts jobBeginner translation
GitRecords versions of project filesA history of saved checkpoints
GitHubStores and shares Git repositories onlineThe project’s online home
VercelBuilds and hosts a website from a repositoryTurns the project into a live address
NamecheapCan register and renew a domainWhere you can buy a name
Cloudflare or Namecheap DNSPublishes records that direct the domainThe internet’s address book

Repository, commit, deploy

  • Repository: the project folder plus its history.
  • Commit: a named checkpoint containing a set of changes.
  • Deploy: make a version available on a hosting service.

Template or fork?

A fork stays connected to the original project and is useful when contributing back. A template starts a separate project with a clean history.

Today, use the template: it creates a project you own without carrying the class repository’s history.

Hands-on · Browser only

5. Put the AI Build Brief online

The starter is plain HTML, CSS, and JavaScript. It contains no API key, login, database, build command, or personal data.

Before you begin

Sign in to GitHub and Vercel. When Vercel asks, connect the GitHub account that owns your new repository.

Step 1 · Make your own repository

  1. Open the AI Build Brief template.
  2. Select Use this template, then Create a new repository.
  3. Choose your GitHub account as the owner.
  4. Give it a short name such as my-ai-build-brief.
  5. Choose Public for this no-secrets class project, then select Create repository.

Create yours from the template ↗

Step 2 · Notice what you own

  • index.html contains the page and its controls.
  • styles.css controls layout, colors, and responsive design.
  • app.js combines the choices and makes the result interactive.
  • README.md explains the project.

Your repository is now separate from the template. Its address begins with github.com/your-name/.

Step 3 · Import the repository into Vercel

  1. Open the Vercel New Project page.
  2. Find your new GitHub repository and select Import.
  3. Leave the project settings at their defaults. No framework preset, build command, or environment variable is needed.
  4. Select Deploy and wait for the success screen.
  5. Open the .vercel.app address and make an idea.

Step 4 · Create a clear request for your AI

  1. On your live AI Build Brief, choose an audience, outcome, and operating style.
  2. Select Create AI brief.
  3. Read the goal, requirements, capability check, and human approval gate.
  4. Select Copy AI brief and paste it into ChatGPT, Claude, Codex, or another AI assistant.
  5. Notice whether it can actually access files. Review its proposed plan before continuing.

The capability check matters: chat can advise and generate content; an agent with project access can inspect, edit, and test files. Neither should claim work it did not perform.

If your repository is missing in Vercel

Check that Vercel is connected to the correct GitHub account and that the Vercel GitHub integration has access to the new repository. Do not create tokens or paste passwords into the project.

Make it yours

6. Edit on GitHub and watch Vercel redeploy

A new commit to the production branch triggers a new Vercel deployment.

  1. In your GitHub repository, open index.html.
  2. Select the pencil icon to edit the file.
  3. Change the introductory sentence or footer text.
  4. Select Commit changes, add a short message, and commit directly to main.
  5. Return to Vercel and watch the new deployment appear.
  6. Refresh your public site and confirm your change.

The full loop

Edit a file → commit the change → GitHub stores it → Vercel deploys it → visitors see it.

For a future project

7. Add your own domain later

Your free .vercel.app address is already a real public website. A custom domain is an optional friendly name.

  1. Register a domain with a registrar such as Namecheap, Cloudflare Registrar, or another provider.
  2. In Vercel, open the project and go to Settings → Domains. Add the domain first.
  3. Vercel displays the exact DNS record required for that domain.
  4. Add that record wherever the domain’s authoritative DNS is managed—perhaps Namecheap, Cloudflare, or Vercel.
  5. Return to Vercel and wait for verification and HTTPS setup.

Namecheap

Namecheap can be the registrar and can also host DNS records. If the domain uses Namecheap BasicDNS, records are managed in its Advanced DNS area.

Namecheap host-record guide ↗

Cloudflare

Cloudflare can register a domain or become its authoritative DNS provider after you change nameservers. DNS records are then managed in Cloudflare.

Cloudflare DNS record guide ↗

One DNS control panel is authoritative

Buying a domain at Namecheap does not mean its DNS must stay there. The nameserver setting decides which provider’s DNS records the internet uses. Before changing nameservers, preserve any website and email records you still need. Follow the exact current values shown by Vercel instead of copying old values from a tutorial.

8. Final recap

  1. Ollama and LM Studio run models locally in different interfaces.
  2. A model that fits is not necessarily a model that runs well; leave memory headroom.
  3. Docker Sandboxes add boundaries, but humans still control access and review results.
  4. Git records versions, GitHub stores the project, and Vercel publishes it.
  5. A registrar sells the domain; authoritative DNS points the name to the host.

Your proof of completion
