Section 5

From Prompts to Agents: Local AI and AI-Native Apps

This final session brings together the main ideas from the course. We will shift from simply chatting with AI to understanding how AI models, apps, APIs, and agents can work together in practical workflows.

Section outcomes

  • Connect the major ideas from Sections 1-4
  • Explain how AI-native apps can turn user intent into tool and API actions
  • Understand what it means to run an AI model locally
  • Watch Ollama run a local model and expose a local API
  • See Codex build a small app that talks to a local Ollama model

How to use this session

This session can be followed as a live demo or reviewed later as a guide. During the live class, these steps are demonstrated. After class, you can use the commands and prompts as a reference if you want to explore local AI on your own.

The goal is to make the ideas visible: a local model running on a computer, an API that apps can call, and an agent-style coding tool building a small app around that model.

1. Review: what mattered from Sections 1-4

The tools will change, but these habits carry forward.

  • Prompt clearly: Say what you want, who it is for, and what format would help.
  • Provide useful context: Give the model the background, examples, constraints, and source material it needs.
  • Remember models are not databases: A model predicts helpful text; it does not automatically know current facts or your private information.
  • Verify AI output: Check important facts, calculations, tone, citations, and anything that affects real decisions.
  • Iterate: Treat AI work as a draft-and-revise process, not a perfect one-shot answer.
  • Think in workflows: The biggest value often comes from connecting steps, tools, files, and review points.

2. AI-native apps

Many future apps may not start with menus and buttons.

A simple pattern

User intent → AI model → Tool/API call → Result → Human review

Instead of clicking through every screen, a user may describe a goal. An AI agent or AI-native app can then use tools, APIs, files, and services to help complete the task.

Traditional apps are not disappearing. Forms, dashboards, buttons, and review screens still matter. The change is that the front door to software is becoming more conversational and goal-driven.

3. Local AI

Local AI means the model runs on your own machine instead of only in a cloud service.

Why it matters

  • A model can run on your own computer.
  • It can be more private because every prompt does not have to leave your machine.
  • It can work without sending each request to a cloud AI service.
  • It helps show that AI can be part of ordinary local apps and workflows.

Tradeoffs

  • Local models may be slower depending on the computer.
  • Smaller models may be less capable than the strongest cloud models.
  • Model size, memory, and hardware matter.
  • This session uses Ollama to run the local model.

4. Ollama in the terminal

These commands show the basic local AI pattern: list available models, prepare the model if needed, run it in the terminal, and call the local API from another program.

Terminal commands

ollama list
ollama pull gpt-oss:20b
ollama run gpt-oss:20b

Example prompts

Explain what an AI agent is to a beginner in five short bullet points.
Give me three examples of useful local AI apps a student could build.

Local API example

curl http://localhost:11434/api/generate \
  -d '{
    "model": "gpt-oss:20b",
    "prompt": "Write a friendly one-paragraph explanation of local AI.",
    "stream": false
  }'

Once a local model has an API, a regular app can talk to it. The app sends a prompt to the local API and receives the model's response.

5. Building an app around local AI with Codex

This example shows how a coding agent can help build a small app that calls the local Ollama API.

App idea: Local AI Study Buddy

The app will have a text box for a question, a model field or dropdown so the model can be changed without editing code, a button labeled Ask Local AI, a response area, a backend route that calls Ollama at localhost:11434, and a clear note that the answer comes from a local model.

Copyable Codex prompt

Build a small local AI Study Buddy app.

The goal is to demonstrate how a normal web app can talk to a local LLM running through Ollama.

Requirements:
- Keep the app simple and classroom-demo friendly.
- Build the app in the current folder selected in Codex Desktop App.
- Use plain Node/Express plus a simple HTML/CSS/JavaScript frontend unless there is an obvious reason to use something else.
- Create a basic web UI with:
  - A title: Local AI Study Buddy
  - A text area for the user's question
  - A model field or dropdown with gpt-oss:20b as the default
  - A button labeled Ask Local AI
  - A response area that shows the model's answer
- Add a small backend endpoint that sends the user's prompt to Ollama at http://localhost:11434/api/generate.
- Use model gpt-oss:20b by default, but keep the model name easy to change from the UI or with OLLAMA_MODEL.
- Use stream: false for simplicity.
- Handle errors gracefully if Ollama is not running, the selected model is missing, or the model response fails.
- Add brief comments where helpful.
- After building, explain:
  - What files you changed
  - How to run the app
  - How the frontend talks to the backend
  - How the backend talks to Ollama
  - What students should notice during the demo
Do not overbuild this. Keep it small, readable, and easy to explain in class.

Run the demo

npm install
npm start

Then open http://localhost:3000.

If port 3000 is busy:

PORT=3015 npm start

6. Agent tools overview

The main trend is movement from chat toward tool use and agent workflows.

Chat and coding agents

  • ChatGPT: Useful for explaining, planning, writing, summarizing, and reasoning.
  • Codex / Claude Code: Coding agents that can work with project files, inspect code, make changes, and explain their work.

Local and persistent agents

  • Ollama / LM Studio: Tools for running local models on your own machine.
  • Hermes / OpenClaw: Examples of more persistent or tool-using agent systems.

7. Closing discussion questions

Use these to connect the demo back to real work and study habits.

  • What kinds of apps become easier when users can describe goals instead of clicking through menus?
  • When would local AI be better than cloud AI?
  • What risks come with agents that can use tools?
  • What should humans still review before trusting AI output?
  • What would you build with a local AI model?

Final takeaway

The durable AI skill is not memorizing one tool. Tools will change. The durable skill is learning how to describe goals, provide context, verify results, and safely delegate work to AI systems.
