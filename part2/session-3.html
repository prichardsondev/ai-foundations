Part 2 - Section 3

RAG: Search First, Then Answer

Retrieval-augmented generation, or RAG, lets an AI answer from selected source material instead of relying only on what the model learned during training. In this lesson, you will understand the moving parts and then build a small RAG help system from a public GitHub repository.

By the end of this lesson, you should be able to

  • Explain RAG in one sentence.
  • Describe what chunks, embeddings, vector search, and retrieved context do.
  • Explain where a vector database fits—and why a tiny learning project may not need one.
  • Separate a retrieval failure from an answer-generation failure.
  • Download and run the RAG Help System tutorial.

1. The central idea

A RAG system searches its approved sources first, then gives the most relevant passages to an answer model.

Without RAG

The model answers from its training and the current conversation. Its knowledge may be missing, stale, too general, or unsupported.

With RAG

The system retrieves relevant passages from your source collection and places them in the prompt. The model can answer from those passages and cite them.

RAG does not retrain the model

The source documents remain outside the language model. They are searched at question time, so they can be updated without training a new model.

2. RAG has two connected stages

One stage prepares the source material. The other uses that prepared material to answer a question.

Stage A: build the searchable index

PDF documents
  -> extract text
  -> split text into chunks
  -> send each chunk to an embedding model
  -> save each chunk, source, and embedding vector

Stage B: retrieve and answer

User question
  -> send the question to the same embedding model
  -> compare the question vector with chunk vectors
  -> retrieve the closest chunks
  -> send question + retrieved chunks to an answer model
  -> return a grounded answer with citations
  -> human checks answer against sources

Do not combine these into one mysterious “AI” step

Retrieval selects source material. Generation writes the answer. Either stage can fail, and you diagnose them differently.

3. Embeddings and vector storage

An embedding model, a vector store, and an answer model have different jobs.

Embedding model

Turns text into a list of numbers called a vector. Text with similar meaning should produce vectors that are closer together.

Vector search

Compares the question vector with stored chunk vectors. A similarity score ranks which chunks are closest to the question.

Answer model

Receives the question and retrieved text. It writes the response, but it did not perform the vector search itself.

Where does a vector database fit?

A vector database stores embeddings with their source text and metadata, then performs fast similarity searches. It becomes valuable when a system has many chunks, needs filtering, supports frequent updates, or serves multiple users.

Learning-sized projectLarger application
Save vectors in JSON and calculate cosine similarity in Python. Store and search vectors in Chroma, pgvector, Pinecone, or another vector database.
Easy to open, inspect, and understand. Better persistence, filtering, indexing, concurrency, and scale.

What this class project does

The tutorial creates real OpenAI embeddings and performs real semantic retrieval. It saves eight small chunk vectors in a local JSON index so you can inspect the mechanics. Replacing JSON and the Python similarity loop with a vector database changes the storage and search layer—not the overall RAG pattern.

4. What you will build

The RAG Help System answers questions about a fictional task application using two short PDF help documents.

The program will

  1. Extract text and page numbers from the PDFs.
  2. Create overlapping chunks.
  3. Create embeddings with text-embedding-3-small.
  4. Save vectors and source metadata locally.
  5. Embed a question and calculate cosine similarity.
  6. Display the three retrieved chunks and their scores.
  7. Generate a cited answer with the OpenAI Responses API.

You will test

  • A question the documents can answer.
  • A question the documents cannot answer.
  • Retrieval without answer generation.
  • An answer in another language while keeping the original citations.
  • Whether every citation names a source that was actually retrieved.

6. Diagnose before you trust

Seeing an answer is not the end of a RAG workflow. Inspect what happened.

What you observeLikely problemWhat to inspect
The correct source was not retrieved.Retrieval failureChunk boundaries, source wording, embedding model, filters, and ranking.
The correct source was retrieved, but the answer is wrong.Generation or grounding failurePrompt, supplied context, unsupported additions, and model behavior.
The documents lack the answer, but the model answers anyway.Grounding failureMissing-answer instruction and human review.
A citation names a source that was not retrieved.Citation failureAllowed citations and the original source text.
A document tells the model to ignore instructions.Prompt injectionTreat document text as untrusted content, never as system instructions.

The final check

Open the cited PDF page. If the source does not support the claim, the answer is not grounded—even when it sounds correct.
