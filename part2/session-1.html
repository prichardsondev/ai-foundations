Part 2 - Section 1

Setup Path: Local Machine to Deployed App

Today we set up the workflow for Part 2: local tools, coding agents, GitHub, and deployment.

1. Course Intro

By the end, you should understand the path from a fresh Raspberry Pi/Linux lab machine to a small local app, a GitHub repository, and a Vercel deployment.

  • Use the terminal with more confidence
  • Install and verify the tools needed for class
  • Use Git and GitHub as a safety net
  • Use Codex carefully with human review
  • Build, commit, push, and deploy a simple app

Safety rule

Do not use private data, passwords, tokens, school records, work records, customer information, employee records, or confidential documents in AI tools. Use course examples, public information, or fictional lab notes.

2. Linux Overview

A terminal command is an instruction. The computer responds with output, an error, or a prompt for more information.

Basic ideas

  • Folder: a place that contains files
  • File: a document, script, image, or app resource
  • Path: the location of a file or folder
  • Command: what you ask the terminal to do
  • Output: the result the terminal prints back
  • Error: a message that something did not work

Starter commands

pwd
whoami
hostname
ls
ls -la
cd ..
mkdir ai-lab
cd ai-lab
clear
history

3. System Check and Update

Instructor-led: update commands may vary by lab image.

Check the machine

df -h
free -h
ip addr
sudo apt update
sudo apt full-upgrade

Read before pressing Y

Read prompts before approving changes. Ask before removing packages, changing system settings, or running commands you do not understand.

4. Install Required Tools

Instructor-led: install only from trusted package sources.

Core tools

sudo apt install -y git curl build-essential ripgrep
  • git: version control
  • curl: downloads from the terminal
  • build-essential: common compile tools
  • ripgrep / rg: fast file search

We want a current LTS version suitable for web app demos and Codex/npm workflows.

Check first

node --version

Install Node LTS if missing

Instructor-led: use the class-approved Node LTS install path for this lab image.

6. Create a GitHub Account

GitHub is where you can store and share the class project.

Account checklist

  • Create a GitHub account
  • Verify your email address
  • Choose your username carefully
  • Do not reuse passwords
  • Enable 2FA if prompted

First app repo

When creating the GitHub repo for this first class app, create it empty. Do not add a GitHub README, license, or .gitignore yet. That avoids confusing first-time merge or pull issues when pushing the local repo.

7. Configure Git

Git needs your name, email, and default branch setting before your first commit.

One-time setup

git --version
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
git config --global init.defaultBranch main
git config --list

Privacy note: use the same email as GitHub, or use GitHub's private noreply email if you prefer not to expose your personal email in commits.

8. Create the Project Folder and Simple Git Overview

Create one course folder, one app folder for today, and then start Git tracking inside the app folder.

Folder and repo setup

cd ~
mkdir -p ai-foundations-part-2
cd ai-foundations-part-2

mkdir ai-lab-notes
cd ai-lab-notes

git init
git branch --show-current
git status

After this step, the first git status happens inside a real repo.

Plain-English meanings

  • repo: tracked project folder
  • git init: start tracking this folder
  • git status: see what changed
  • git add: choose what to include in the checkpoint
  • git commit: save the checkpoint
  • git remote: connect to GitHub
  • git push: send the checkpoint to GitHub

Common flow

git status
git add .
git commit -m "Create AI Lab Notes app"
git remote add origin YOUR_GITHUB_REPO_URL
git push -u origin main

9. Install VS Code or Fallback Editor

Use a code editor if it works on the lab machine. Do not let editor setup stop the class.

Try VS Code

sudo apt install -y code
code .

Fallback is fine

VS Code support on Raspberry Pi can vary. If it fails, use a terminal editor, browser-based editing, or an instructor fallback.

10. Install Codex Agent

Codex can inspect files, make edits, and run commands, but you stay in charge of review and approvals.

Official standalone installer

curl -fsSL https://chatgpt.com/codex/install.sh | sh
codex --version

Optional npm path

Use this only if Node/npm is ready and the instructor confirms this path for the lab.

npm install -g @openai/codex
codex --version

Install only official Codex

Install only the official OpenAI Codex CLI / @openai/codex. Do not install random Codex UI wrappers or unofficial packages.

11. First Safe Codex Prompt: Inspect Only

Start with a no-edit prompt so you can compare Codex's answer with the actual folder.

Copy this prompt into Codex

Please inspect this folder and tell me:

1. What kind of project this is
2. What files are most important
3. How to run it locally
4. What Git branch I am on
5. Whether there are uncommitted changes

Do not edit files yet.

12. Codex Builds a Simple Class App

The project is AI Lab Notes: a small Vite app with no backend, no API keys, and no private data.

App requirements

  • Class setup checklist
  • Linux/Git command cheat sheet
  • Fictional lab notes form saved to localStorage
  • Clean responsive design
  • README with run, build, GitHub, and Vercel deployment steps

Checkpoint before Codex edits

pwd
git status

Confirm you are inside ~/ai-foundations-part-2/ai-lab-notes before asking Codex to build.

Copy this prompt into Codex

Build a small beginner-friendly Vite web app called AI Lab Notes in the current ai-lab-notes folder. The app should include a setup checklist, a Linux/Git command cheat sheet, and a fictional lab notes form saved in localStorage. Do not use external APIs, passwords, tokens, private data, or paid services. Add a README with install, run, build, GitHub, and Vercel deployment steps. Before editing, briefly explain your plan.

13. Review Before Saving

Codex output is a draft. Review the files and run the app before committing.

Review commands

git status
git diff
npm install
npm run dev
npm run build

For the Vite path, these npm commands should be documented in the README Codex creates.

14. Codex Helps Push to GitHub

Codex can prepare the commands, but review before pushing.

Prompt Codex to prepare

Review the project and prepare it for GitHub. Show me the git status, summarize the files that changed, suggest a commit message, and then ask before running git add, git commit, or git push.

Final commands you may run

git add .
git commit -m "Create AI Lab Notes app"
git remote add origin YOUR_GITHUB_REPO_URL
git push -u origin main

15. Create Free Vercel Account and Deploy

Vercel gives the class a simple path from GitHub repo to public URL.

Deployment checklist

  • Create a free Vercel/Hobby account
  • Connect GitHub
  • Import the app repository
  • Deploy
  • Copy the public URL

After GitHub is connected, future pushes can trigger new deployments.

16. Closing Checklist

By the end of class, you should know where you are in the workflow.

Ready or ready to finish

  • GitHub account created and verified
  • Git configured
  • Node/npm working
  • Codex installed and verified
  • Simple app runs locally
  • Repo pushed to GitHub
  • Vercel account created
  • App deployed or ready to deploy
  • You understand that human review stays in charge
