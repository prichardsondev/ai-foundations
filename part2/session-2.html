Run Local Models and Understand Inference

Today we run a local model, compare local and cloud AI workflows, and learn the practical tradeoffs behind model size, speed, privacy, context, and reliability.

What you'll take away

  • Explain why local AI is useful even when it is not the most powerful option
  • Compare local, cloud, and hybrid AI workflows
  • Identify when a smaller local model is good enough for a task
  • Explain inference, training, fine-tuning, and context windows in plain language
  • Recognize how model size and hardware affect quality and speed
  • Run a local model and review its output with realistic expectations

Safety rule

Use fictional, public, or course-provided examples. Do not paste private data, passwords, tokens, school records, work records, customer information, employee records, or confidential documents into any AI tool.

1. Why Local AI Belongs in Your Stack

Local AI is usually not more powerful than the best cloud AI models. The point is not that local is always better. The point is that local can be good enough, available, private, and under your control.

Practical framing

Cloud models can change quickly. A model can be renamed, restricted, repriced, removed, or replaced because of company policy, legal requirements, safety decisions, or government action. If your workflow depends completely on one hosted model, your workflow depends on that model staying available.

Local AI gives you another option. If your hardware can run a model that is good enough for the task, it becomes a useful tool in your stack.

  • Use cloud AI when you need the strongest available model.
  • Use local AI when privacy, continuity, cost control, offline use, or hands-on learning matter.
  • Use both when a hybrid workflow makes the most sense.

Good enough matters

A smaller local model may not win benchmarks, but it may be perfectly useful for drafts, summaries, class demos, simple code help, document search, and learning how AI systems work.

Hosted access can change

In June 2026, Anthropic had to abruptly disable access to Fable 5 and Mythos 5 after a U.S. government directive. Whatever the reason, the lesson for this course is simple: hosted AI access can change. Local AI gives you a fallback.

2. Local, Cloud, and Hybrid

Choose the workflow based on the task, not on a slogan.

Local

  • Runs on your machine
  • Can work offline after setup
  • Good for learning and private experiments
  • Limited by hardware and model size

Cloud

  • Usually stronger models
  • Easy to start using
  • Depends on provider access and policies
  • Requires careful data-sharing decisions

Hybrid

  • Use local for private or repeatable work
  • Use cloud for harder reasoning or polish
  • Keep humans reviewing key outputs
  • Document which tool handled which step

3. Inference Basics

Inference is what happens when a trained model responds to your prompt.

Three terms

  • Training: creating the model from large datasets
  • Fine-tuning: adjusting a model for a narrower pattern or task
  • Inference: running the model to generate an answer

What affects output

  • Model size and quality
  • Available memory and processor speed
  • Prompt clarity
  • Context window size
  • Whether the model has the right source material

4. Context Windows and Forgetting

A model can only work with the context it currently has available.

Plain-English idea

The context window is the model's working space for the current prompt, chat, files, and instructions. If important information is outside that window or never provided, the model may guess, miss details, or lose track of earlier instructions.

This is one reason retrieval matters later in the course: when files matter, we need a workflow that brings the right source material into the prompt at the right time.

6. Compare Outputs

Run the same safe prompt locally and in a cloud tool, then compare the result.

Comparison checklist

  • Which answer is clearer?
  • Which answer follows the prompt better?
  • Which answer is faster?
  • Which answer needs more fact-checking?
  • Which workflow better fits privacy, cost, continuity, and learning needs?
